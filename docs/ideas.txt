Re-measure before re-prioritising; these numbers drive the sections below.

Scale (bigger than the "4 downloads" we had been assuming):
  - 74 people seen in PostHog, 49 "Application Installed", 48 registered users
  - 48 careers, 10,648 matches simulated, 2.4M balls bowled
  - Growth is accelerating: 8 / 11 / 12 new careers in the last three full weeks
  - 100% of users are on app version 1.0.0 — we have never shipped an update

The core problem is RETENTION, not acquisition:
  - 47 of 74 people (64%) used the app on exactly ONE day and never returned
  - only 9 people were ever active on 4+ separate days
  - 23 of 48 careers are stale (untouched for 14+ days); 17 active in last 7 days
  - 13 users deleted their account outright

But engaged users are VERY engaged (the game itself is working):
  - 27 of 48 careers have played 71+ matches; 16 have played 200+
  - deepest careers have completed 20, 19, and 14 seasons
  - so the retention cliff is in the FIRST SESSION, not in the core loop

First-run funnel leaks, in order of size:
  - 8 of 48 registered users never created a career at all
  - 10 careers never played a single match; 5 of those were created and
    abandoned within ~1 minute, sitting in the mega-draft
  - tutorial: 47 started, only 29 completed, 24 skipped
  - NOTE: careers sitting in phase='draft' are NOT all stuck beginners — that
    cohort averages 330 matches (they are between-season re-drafts). Only the
    zero-match ones are true drop-offs. Don't confuse the two.

Platform mix (justifies the iPad work):
  - 9 of 74 users are on iPadOS (~12%)
  - ~5 users still on iOS 16/17 — keep the deployment target low
  - device model was NOT captured at the time of this snapshot — every install
    reported "Mobile" with no model, so the iPad share above is inferred from
    $os_name. Fixed 2026-08-18; real models arrive from the next release on.

Analytics & Instrumentation
  - (done 2026-08-18) Gameplay funnel events: draft_started, draft_completed,
    match_played (live vs quick_sim, with a count), playoffs_reached,
    season_completed. Derived centrally from league-payload transitions in
    use-funnel-tracking.ts rather than from buttons, because a draft can end via
    autodraft or the last manual pick and a match can finish from several
    screens — per-call-site capture misses paths, and a missed path is invisible.
    Every event carries competition / match_format / career_mode.
  - (done 2026-08-18) $device_model / $device_type from expo-device, whose
    DeviceType separates TABLET from PHONE. Previously every install reported
    "Mobile" with no model, so iPad users could only be inferred from $os_name.
  - Still open: draft_abandoned. Needs a session-end signal, which the client
    cannot observe reliably; likelier derived server-side from careers that sit
    in phase="draft" with zero matches past some age.
  - Still open: screen-view events per tab. PostHog autocapture has
    captureScreens enabled but no $screen events are arriving, so expo-router
    navigation is not being picked up — needs manual instrumentation.
  - Still open: Sentry read auth token, so crash-free-session rate can go in the
    release checklist. We ship blind to crash rates today. (The DSNs in
    secrets/ids.txt are ingest-only; they cannot read issues back. This also
    blocks source-map upload — see build(mobile) notes and make mobile-xcode-env.)
  - App version tagging already works: PostHog reports $app_version, which is how
    we know every user is still on 1.0.0.

Retention — first session  ** the 64% one-and-done problem **
  - The mega-draft is the most likely first-run wall: it is long, it is the
    default for new careers, and 5 careers were abandoned inside it within a
    minute. Options: a "quick draft / auto-draft my squad" escape hatch, a
    visible progress indicator, and the ability to resume a draft later.
  - Make "2026 Rosters (No Draft)" the recommended/default option for a first
    career so a brand-new user reaches an actual match fast, and offer the
    mega-draft as the deliberate, richer choice.
  - Tutorial completion is only 62% — shorten it, make skipping non-terminal,
    and let users replay it from Settings.
  - Get the user to their first MATCH within the first session; that is the
    moment the product proves itself (people who reach it play 71+ matches).
  - Re-engagement: we have local notifications, but 23 careers are stale.
    A "your season is waiting — N matches left" nudge is worth testing.

App Store rating & feedback
  - In-app rating prompt via StoreKit's SKStoreReviewController
    (expo-store-review). Trigger it on a genuine high point — winning a
    trophy, completing a first season, or a milestone century — never on
    launch and never during a match. iOS caps prompts at 3/year per user,
    so spend them only on users who have already shown engagement.
  - Gate the prompt behind a positive signal (e.g. 2+ seasons completed) so
    we bias the sample toward users likely to leave 4-5 stars.
  - Add an in-app "send feedback" path that is NOT the App Store, so unhappy
    users have somewhere to go other than a 1-star review.
  - Ask for the rating only after the app has been updated at least once, so
    reviews reflect the current build rather than 1.0.0.
